# VaultSpace AI Query System: Phase 0 exit review

Date: 2026-10-17
Starting commit: `e6a7e21`
Review state: **Engineering work complete; product and privacy acceptance pending**
Recommendation: **Proceed to Phase 1 with synthetic data and customer AI disabled**

## Objective and boundary

Phase 0 established an auditable provider decision, current-system inventory, source and privacy rules, repeatable synthetic staging fixtures, a frozen initial question set, and a retrieval feasibility result. It did not build or enable the assistant. No customer document content was sent to a model. Sarah's Organization and CloudVault Series A were not used as QA fixtures. All Azure changes were in Munger subscription 1; no Medau subscription was changed.

## Review cycles

| Review                     | Challenge                                                                                                                                                                | Disposition                                                                                                                                                                                                                |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Strawman                   | Place every room document into one model corpus and gate chat solely on room membership. This can disclose hidden, stale, withdrawn, or unindexed content.               | The Phase 2 gate enumerates every active room document from the authoritative database, then separately requires complete current-version indexing. Candidate context and final citations are reauthorized.                |
| Steelman                   | A room-wide all-document gate can deliver useful Q&A before the harder partial-access release if it is evaluated server-side on every query and denies incomplete rooms. | Adopted as a temporary Phase 2 scope. Phase 4 remains the full per-document and scoped-link solution.                                                                                                                      |
| Premortem                  | A stale version, malicious document instruction, link revocation, workbook arithmetic mistake, provider fallback, or spend spike causes harm after apparent QA success.  | Current-source and final-response checks, untrusted-source treatment, link tests, deterministic finance lane, no silent provider fallback, default-off flags, and cost limits were made explicit phase gates.              |
| Architecture audit         | An unrelated AI resource, ordinary search rows, or an Azure-native ACL could be mistaken for an approved VaultSpace corpus.                                              | A dedicated account was provisioned; a separate source resolver and index are specified; the permission engine remains authoritative.                                                                                      |
| Security and privacy audit | Raw content might leak through logs, model storage, cross-tenant retrieval, or conversation history.                                                                     | Bounded context, metadata-only telemetry, stateless model calls, source revalidation, zero-leak tests, and a pending retention approval were recorded. Azure abuse-monitoring terms still need product/privacy acceptance. |
| QA and operations audit    | A passing vector microbenchmark or 18 questions could be overread as production quality.                                                                                 | The result is labeled feasibility only. Phase 1 and 2 require realistic load, RLS, expanded golden sets, browser journeys, rollback, and incident rehearsal.                                                               |

These were engineering reviews of the plan and environment, not an independent security certification. Independent code and security review is required on the Phase 1 and Phase 2 implementation before release.

## Remaining decisions and release blockers

1. **Product/privacy acceptance:** approve or revise the Foundry US data-zone path, Azure abuse-monitoring terms, no provider-hosted file store, and the proposed 30-day post-pilot conversation-history default. Until accepted, use synthetic data only and persist no chat history.
2. **Phase 1 control checks:** confirm local-auth key rejection after Azure propagation without exposing a key; decide on private networking or explicit egress restrictions for production; add tested cost alerts or provider cost control and application token/request bounds before customer opt-in.
3. **Phase 1 retrieval proof:** test RLS and raw-query isolation on a disposable database, realistic source distributions and concurrent traffic, vector deletion, lifecycle reconciliation, index rebuild, and full request latency. Reconsider the retrieval engine if those gates fail.
4. **Phase 2 release proof:** expand the golden set, score live model answers and search, validate citations and revocation races, test prompt injection and links, and rehearse a timed rollback. No customer feature flag may be enabled on Phase 0 evidence alone.

## Decision

The Phase 0 engineering baseline meets the synthetic-development exit criteria. Start Phase 1 behind disabled customer flags. Keep GitHub issue 221 open until the product/privacy decision is recorded; close it only after that acceptance is attached. Customer content and customer-facing AI remain blocked by the later security, QA, and release gates.
